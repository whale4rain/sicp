# 1.1 The Elements of Programming

> Lab: [SICP 1.1 Lab](../labs/sicp-1-1-lab.html) · Next: [1.2 Procedures and the Processes They Generate](1.2.md)

**Big idea:** every powerful language gives you three things: **primitive expressions**, **means of combination** (build compound things from simpler ones) and **means of abstraction** (name compound things and use them as units). The rest of the book is these three ideas applied to procedures (ch 1), data (ch 2), state (ch 3) and languages themselves (ch 4).

## 1.1.1 Expressions
- A **combination** is a list in parentheses: `(operator operand ...)`. The leftmost element is the operator.
- **Prefix notation**: `(+ 21 35 12 7)` takes any number of arguments and nests without precedence rules: `(+ (* 3 5) (- 10 6))`.
- The interpreter runs a **read-eval-print loop** (REPL): read an expression, evaluate it, print the value.

## 1.1.2 Naming and the environment
- `(define size 2)` associates the name `size` with the value `2`.
- The memory that keeps track of name–value pairs is the **environment** (here, the *global* environment). Naming is the simplest means of abstraction.

## 1.1.3 Evaluating combinations
To evaluate a combination:
1. Evaluate the operator and every operand.
2. Apply the procedure (the operator's value) to the arguments (the operands' values).

- The rule is **recursive**: step 1 calls the rule again on each subexpression. Picture the expression as a tree; values percolate up from the leaves (**tree accumulation**).
- Leaves: numbers evaluate to themselves, built-in operators to their procedures, names to their value in the environment.
- **Special forms** are exceptions to this rule, each with its own evaluation rule. `define` is the first one: `(define x 3)` does not evaluate `x`.

## 1.1.4 Compound procedures
```scheme
(define (square x) (* x x))
(define (sum-of-squares x y) (+ (square x) (square y)))
(define (f a) (sum-of-squares (+ a 1) (* a 2)))
(f 5)   ; 136
```
- General form: `(define (<name> <formal parameters>) <body>)`.
- A compound procedure is used exactly like a primitive. You can't tell `square` from `*` by how you call it. That uniformity is what makes abstraction work.

## 1.1.5 The substitution model
To apply a compound procedure: evaluate the body with each formal parameter replaced by the corresponding argument.
```
(f 5)
(sum-of-squares (+ 5 1) (* 5 2))
(sum-of-squares 6 10)
(+ (square 6) (square 10))
(+ (* 6 6) (* 10 10))
(+ 36 100)
136
```
- **Applicative order** ("evaluate the arguments, then apply"): what Lisp actually does. Each argument is evaluated once.
- **Normal order** ("fully expand, then reduce"): substitute operand *expressions* and evaluate only when a primitive needs a value. `(+ 5 1)` would be computed twice in `(f 5)`.
- Both give the same answer whenever the procedures are well-behaved (no side effects, every argument terminates). Exercise 1.5 is the case where they differ.
- The substitution model is a way to *think*, not how interpreters work, and it breaks once assignment arrives in chapter 3 (replaced by the **environment model**).

## 1.1.6 Conditional expressions and predicates
```scheme
(define (abs x)
  (cond ((> x 0) x)
        ((= x 0) 0)
        ((< x 0) (- x))))

(define (abs x)
  (if (< x 0) (- x) x))
```
- `cond` takes **clauses** `(<predicate> <expression>)`, evaluated top to bottom. The first predicate that is true selects its expression; the rest are never evaluated. `else` is a predicate that is always true.
- `if` is the two-way case: `(if <predicate> <consequent> <alternative>)`. It evaluates the predicate, then **only one** branch.
- `and` and `or` are special forms too: they stop as soon as the answer is known (short-circuit). `not` is an ordinary procedure.
- A **predicate** is a procedure or expression that returns true or false (`#t`/`#f`). Anything other than `#f` counts as true.

## 1.1.7 Example: square roots by Newton's method
```scheme
(define (sqrt-iter guess x)
  (if (good-enough? guess x)
      guess
      (sqrt-iter (improve guess x) x)))
(define (improve guess x) (average guess (/ x guess)))
(define (average x y) (/ (+ x y) 2))
(define (good-enough? guess x) (< (abs (- (square guess) x)) 0.001))
(define (sqrt x) (sqrt-iter 1.0 x))
```
- Mathematics describes *what is* (√x is the y ≥ 0 with y² = x): **declarative** knowledge. Programs describe *how to*: **imperative** knowledge.
- Iteration without a loop construct: `sqrt-iter` calls itself. (1.2.1 shows why this costs no extra space.)
- Start with `1.0`, not `1`, or Scheme does exact rational arithmetic and the fractions grow huge.

## 1.1.8 Procedures as black-box abstractions
- The problem splits naturally into `good-enough?`, `improve`, `sqrt-iter`. Each is a **procedural abstraction**: callers care *what* it computes, not *how*.
- **Bound variables**: formal parameters are local. Renaming them consistently changes nothing. Names that aren't bound in a procedure are **free** (`abs`, `<`, `square` inside `good-enough?`).
- **Block structure**: put helpers inside the procedure that uses them so they don't clutter the global namespace.
- **Lexical scoping**: inner procedures can see the outer procedure's parameters, so `x` no longer has to be passed around:
```scheme
(define (sqrt x)
  (define (good-enough? guess) (< (abs (- (square guess) x)) 0.001))
  (define (improve guess) (average guess (/ x guess)))
  (define (sqrt-iter guess)
    (if (good-enough? guess) guess (sqrt-iter (improve guess))))
  (sqrt-iter 1.0))
```

## Pitfalls
- `if` and `cond` **must** be special forms. If `if` were an ordinary procedure, applicative order would evaluate both branches, and a recursive branch would never stop. That's exercise 1.6.
- A fixed tolerance like `0.001` fails for very small numbers (too loose) and very large ones (can loop forever because floats can't get that close). Exercise 1.7 fixes it by stopping when the guess barely changes.
