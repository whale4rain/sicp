# 1.3 Formulating Abstractions with Higher-Order Procedures

> Previous: [1.2](1.2.md) · Lab: coming in week 4

**Big idea:** procedures that take procedures as arguments or return them as values (**higher-order procedures**) let you name *patterns of computation*, not just computations. This is where `map`, `filter`, `reduce`, callbacks and closures come from.

## 1.3.1 Procedures as arguments
Three procedures that look different share one shape:
```scheme
(define (sum-integers a b) (if (> a b) 0 (+ a (sum-integers (+ a 1) b))))
(define (sum-cubes a b)    (if (> a b) 0 (+ (cube a) (sum-cubes (+ a 1) b))))
(define (pi-sum a b)       (if (> a b) 0 (+ (/ 1.0 (* a (+ a 2))) (pi-sum (+ a 4) b))))
```
Abstract the parts that vary (`term` and `next`) into parameters:
```scheme
(define (sum term a next b)
  (if (> a b)
      0
      (+ (term a) (sum term (next a) next b))))

(define (inc n) (+ n 1))
(define (sum-cubes a b) (sum cube a inc b))
```
- This is the mathematician's Σ written as a procedure. Once you have it, you can use it to build further things, like numerical integration:
```scheme
(define (integral f a b dx)
  (define (add-dx x) (+ x dx))
  (* (sum f (+ a (/ dx 2.0)) add-dx b) dx))
```
- Exercises 1.30–1.33 generalize further: iterative `sum`, `product`, `accumulate` (combine with any operation), `filtered-accumulate`.

## 1.3.2 Constructing procedures using lambda
```scheme
(lambda (x) (+ x 4))                       ; a procedure with no name
(sum (lambda (x) (* x x x)) 1 inc 10)      ; no need to define cube first
```
- `(define (plus4 x) (+ x 4))` is exactly `(define plus4 (lambda (x) (+ x 4)))`. Naming and creating a procedure are separate acts.
- **`let`** creates local variables:
```scheme
(let ((a 1)
      (b 2))
  (+ a b))
;; is syntactic sugar for
((lambda (a b) (+ a b)) 1 2)
```
- The variables in a `let` are computed *outside* the `let`, so `(let ((x 3) (y (+ x 2))) ...)` uses the outer `x` for `y`.
- Use `define` for internal procedures, `let` for local values.

## 1.3.3 Procedures as general methods
- **Half-interval method**: if f(a) < 0 < f(b), f has a zero between a and b. Check the midpoint, keep the half where the sign changes. Θ(log(L/T)) steps for interval length L and tolerance T.
- **Fixed points**: x is a fixed point of f if f(x) = x. For some f, repeatedly applying f from a guess converges:
```scheme
(define (fixed-point f first-guess)
  (define (close-enough? v1 v2) (< (abs (- v1 v2)) tolerance))
  (define (try guess)
    (let ((next (f guess)))
      (if (close-enough? guess next) next (try next))))
  (try first-guess))
```
- √x is a fixed point of y ↦ x/y, but that oscillates forever. **Average damping** (use y ↦ ½(y + x/y)) makes it converge, and gives back Newton's sqrt from 1.1.7.
- The golden ratio is the fixed point of x ↦ 1 + 1/x (exercise 1.35).

## 1.3.4 Procedures as returned values
```scheme
(define (average-damp f)
  (lambda (x) (average x (f x))))

(define (sqrt x)
  (fixed-point (average-damp (lambda (y) (/ x y))) 1.0))
```
- `average-damp` takes a procedure and **returns a new procedure**. The returned lambda remembers `f`: that's a **closure** (chapter 3 explains how).
- **Newton's method** is itself a fixed-point search: a zero of g is a fixed point of x ↦ x − g(x)/Dg(x).
```scheme
(define (deriv g)
  (lambda (x) (/ (- (g (+ x dx)) (g x)) dx)))
(define (newton-transform g)
  (lambda (x) (- x (/ (g x) ((deriv g) x)))))
(define (newtons-method g guess)
  (fixed-point (newton-transform g) guess))
```
- **Abstractions and first-class procedures**: an element is **first-class** if it can be named, passed as an argument, returned as a result and stored in data structures. In Lisp, procedures have all four rights. Look for the underlying abstraction and build on it, but don't abstract for its own sake.
